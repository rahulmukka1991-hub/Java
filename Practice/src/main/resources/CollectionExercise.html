Java Practice Exercises

Topics: Collections and Exception Handling

Practice basic Java programming using ArrayList, HashMap, HashSet, built-in exceptions, and custom exceptions.

1. Introduction

The purpose of these exercises is to understand basic Java Collections and Exception Handling through simple programming problems.

Learning Objectives

  • Understand ArrayList, HashMap, and HashSet.
  • Add, search, and retrieve collection elements.
  • Handle built-in Java exceptions.
  • Create and handle custom exceptions.
  • Validate user input.
  • Prevent application crashes caused by invalid input.

Exercise 1: Student Name Management

Beginner

Problem Statement

Create a Java program to store student names in an ArrayList. The program should allow users to add a student name, search for a student, and display all student names. It must prevent duplicate names and reject empty names using exception handling.

Requirements

  1. Store student names in an ArrayList<String>.
  2. Allow users to add student names.
  3. Display all stored student names.
  4. Search for a student by name.
  5. Prevent duplicate student names.
  6. Throw an exception when an empty name is entered.
  7. Handle exceptions and display meaningful messages.

Acceptance Criteria

  • A valid student name is added successfully.
  • A duplicate name is not added.
  • An empty name is rejected.
  • Searching for an existing student displays a success message.
  • Searching for a nonexistent student displays a not-found message.
  • The program does not terminate unexpectedly due to invalid input.
Concepts: ArrayList, add(), contains(), isEmpty(), IllegalArgumentException, try-catch.

Exercise 2: Number List with Exception Handling

Beginner

Problem Statement

Create a Java program that accepts numbers from the user and stores them in an ArrayList<Integer>. Display all entered numbers and calculate their sum. Handle invalid numeric input without crashing. The user can type done to stop entering numbers.

Requirements

  1. Accept multiple numbers from the user.
  2. Store valid numbers in an ArrayList.
  3. Display all entered numbers.
  4. Calculate and display the sum.
  5. Handle invalid numeric input using exception handling.
  6. Stop accepting input when the user enters "done".
  7. Handle an empty list appropriately.

Acceptance Criteria

  • Valid integers are stored in the list.
  • The sum is calculated correctly.
  • Entering "abc" displays an error instead of crashing.
  • Entering "done" stops the input process.
  • An empty list produces a sum of zero.
  • Previously entered numbers remain stored after invalid input.
Concepts: ArrayList, loops, Integer.parseInt(), NumberFormatException, try-catch, Scanner.

Exercise 3: Employee ID Search

Beginner

Problem Statement

Create a Java program that stores employee IDs and employee names in a HashMap<Integer, String>. Allow users to search for an employee using an ID. If the ID does not exist, throw and handle a custom EmployeeNotFoundException.

Requirements

  1. Store employee IDs and names in a HashMap.
  2. Add at least five employee records.
  3. Accept an employee ID from the user.
  4. Search for an employee using the entered ID.
  5. Display the employee name when the ID exists.
  6. Create a custom EmployeeNotFoundException.
  7. Throw the exception when the employee ID does not exist.
  8. Catch the exception and display a meaningful message.

Acceptance Criteria

  • An existing employee ID displays the correct employee name.
  • A nonexistent employee ID throws EmployeeNotFoundException.
  • The exception is caught and an appropriate message is displayed.
  • The program continues running after an unsuccessful search.
Concepts: HashMap, put(), get(), containsKey(), custom exceptions, throw, throws, try-catch.

Exercise 4: Unique Product Names

Beginner

Problem Statement

Create a Java program that stores product names in a HashSet<String>. Allow users to add products and check whether a product exists. Duplicate products must not be stored more than once, and empty product names must be rejected.

Requirements

  1. Store product names in a HashSet.
  2. Allow users to add product names.
  3. Display all stored products.
  4. Check whether a product exists.
  5. Reject empty names using IllegalArgumentException.
  6. Display a message when a duplicate product is entered.
  7. Handle invalid input appropriately.

Acceptance Criteria

  • A new product is added successfully.
  • A duplicate product is not stored twice.
  • An empty product name is rejected.
  • Searching for an existing product returns true.
  • Searching for a nonexistent product returns false.
  • Meaningful messages are displayed for each operation.
Concepts: HashSet, add(), contains(), size(), IllegalArgumentException, exception handling.

Exercise 5: Safe List Element Access

Beginner

Problem Statement

Create a Java program that stores five integers in an ArrayList<Integer>. Ask the user to enter an index and display the element at that position. Handle invalid indexes and non-numeric input without crashing.

Requirements

  1. Store five integers in an ArrayList.
  2. Ask the user to enter an index.
  3. Display the element at the specified index.
  4. Handle IndexOutOfBoundsException.
  5. Handle non-numeric input appropriately.
  6. Display a meaningful message when the index is invalid.

Acceptance Criteria

  • An index from 0 to 4 displays the correct element.
  • Entering -1 displays an appropriate error message.
  • Entering 5 displays an appropriate error message.
  • Non-numeric input does not crash the program.
  • Invalid indexes are handled using exception handling.
Concepts: ArrayList, get(), index-based access, IndexOutOfBoundsException, NumberFormatException, try-catch.

7. General Technical Requirements

  1. Use Java to implement the solution.
  2. Use the collection specified in each exercise.
  3. Follow proper variable and class naming conventions.
  4. Handle exceptions using appropriate try-catch blocks.
  5. Display meaningful error messages.
  6. Avoid empty catch blocks.
  7. Do not add invalid data to collections.
  8. Test both valid and invalid inputs.
  9. Keep the solution simple and readable.
  10. Use comments where necessary.
